# M1: `.pix` → IR → Figma for ordinary nodes

Status: **plan, second edition (2026-10-05); part P0 done and reviewed (branch `claude/m1-p0`), A–E not started.** It implements
the M1 row of `docs/REWRITE.md` (§10) and follows its §3, §4, §6–§8 and §11. The first edition was reviewed
independently; every review point is folded in below, and §13 lists where each one went and the few that measurements
contradicted. Part P0 commits this file and the frozen contract of §5; §14 records where implementing P0 made the
contract more precise than this plan said (rows 22-31 come from a review of P0 before A-E start), and the text of
§5 is corrected to match. Part F adds the results.

**Evidence.** Every number is a count from read-only scripts run on three local `.pix` files: **D**, the test design
file (9 372 stored nodes); **K**, the test kit (86 578); **M**, a Сова-based product file (40 472). Three numbers
in a row are D / K / M. The scripts and their outputs stay outside this public repository (REWRITE.md §8). Labels:
**C** confirmed (measured), **I** inferred, **A** assumed (needs a probe).

## 1. Measurements made for this plan

### 1.1 Booleans (C)

Method: rasterise, in the boolean's own frame, its stored `fillGeometry` and the operands' geometry (each operand's
`fillGeometry` under its `transform`; RECTANGLE and ELLIPSE from their size), apply the operation per cell (XOR as
parity), and compare by intersection over union. 240 cells across the longer side (at least 0.05 px), cubics cut into
16 segments, hidden operands left out (there are 0 / 0 / 1). Class A: every visible operand has fill geometry and none
has a visible stroke. Class B: an operand that only strokes, or one with no fill geometry.

| | D | K | M |
|---|---|---|---|
| BOOLEAN_OPERATION | 62 | 228 | 59 |
| own fill visible | 62 | 228 | 59 |
| class A | 62 | 215 | 20 |
| class A: stored result = the operation of the operands (overlap ≥ 0.99) | 62 / 62 | 215 / 215 | 20 / 20 |
| class B | 0 | 13 (all on user pages) | 35 |
| class B: stored result = the operation of the operands' fills | — | 3 / 13 | 1 / 35 |
| operands with a visible stroke | 0 | 32 (30 LINE, 2 VECTOR) | 63 |
| stored nodes under class B booleans | 0 | 80 (12 of them class A booleans, no INSTANCE) | 64 |
| no operand and no geometry | 0 | 0 | 4 |
| union of operands vs stored result, non-union booleans | 6 / 7 below 0.80 | 54 / 62 below 0.80 | — |

For class B the stored result is close to the outline of the operands' strokes (K: three 1 px lines give an
8.8 px square result); neither the fills nor the stored `strokeGeometry` of the operands reproduce it within 0.95.
Pixso's SVG renders of 988 boolean subtrees use the boolean's own fill in 601 of the 601 that carry an rgb fill, and
a child-only colour in 0 (an earlier MCP-era measurement on other files). FINDINGS round 3's file is not among the
local files, so its "own fill inert" count cannot be re-measured; F corrects FINDINGS with this table.

### 1.2 Side strokes against the stored stroke-area path (C)

Population: non-instance FRAME, SYMBOL, RECTANGLE and SECTION nodes with a visible stroke, style definitions excluded.
The oracle samples five points along each side, away from the corners, at the middle of the band the side would
draw (INSIDE: inside the box; CENTER: on the edge; OUTSIDE: outside; absent align: both), against
`strokePaddingPath`. Rule under test: no `border*Weight` field means four sides at `strokeWeight`; any field present
means a missing side is 0.

| | D | K | M |
|---|---|---|---|
| population | 355 | 3 890 | 1 516 |
| oracle available (solid stroke, stroke-area path, both sides ≥ 2 px) | 239 | 2 235 | 1 295 |
| rule = oracle | 237 | 2 235 | 1 295 |
| rule ≠ oracle (become SIDE_RULE_UNPROVEN) | 2 (RECTANGLE, four equal fields, path draws two sides) | 0 | 0 |

The review's 33 / 158 disagreements came from one mid-side probe at 0.25 px over a population that includes dashed
borders (dash gaps read as "no side"); the whole-side probe above finds none on a node without border fields.
INSTANCE nodes are not in the table: their own fields do not decide their border (29 / 837 / 0 with four zero fields
draw four sides; 0 / 1 / 137 with four equal fields draw none) and M1 draws no stroke on a placeholder.

## 5. Contracts (part P0, merged before any parallel work)

### 5.1 IR version 2 (`tools/ir/schema.mjs`, `tools/ir/props.mjs`, `tools/ir/validate.mjs`, `tools/test-ir.mjs`, `docs/IR.md`)

- `VERSION = 2`: `schema.mjs:21`; `test-ir.mjs:29` and :108 (the unknown-version case becomes `VERSION + 1`);
  IR.md:1, :61, :85, :404 and §15. No IR has been written, so there is no migration.
- New `schema.mjs` exports, `export const` at line start, ES2015, no import (`test-ir.mjs:266-286`):
  - `VECTOR_TYPES = ["VECTOR","LINE","STAR","POLYGON","BOOLEAN_OPERATION"]`;
  - `IR_OWN_PROPS` (IR.md:177-187) plus `oracleFillGeometry` (interned, joins INTERNED_PROPS) and `oracleSides`
    (four booleans);
  - `SUPERSEDED_PROPS = ["x","y","rotation","strokeTopWeight","strokeRightWeight","strokeBottomWeight",
    "strokeLeftWeight","topLeftRadius","topRightRadius","bottomRightRadius","bottomLeftRadius"]`;
  - `CODE`: a frozen map from every REASON_CODES key to itself. New code writes codes only as `CODE.X`;
  - `SETTINGS` gains `booleans: ["auto","native","flatten"]` and `spaceEvenlySingle: ["between","center"]`, with
    their SETTING_FLAGS, and `SETTING_DEFAULTS` holds every setting's default;
  - also (P0): `NATIVE_VECTOR_TYPES`, `GEOMETRY_PROPS`, `ORACLE_PROPS` (`oracleFillGeometry`, `oracleSides`: stripped
    from tasks), `SUPERSEDED_BY`, `ORACLE_CLASSES`, `GEOMETRY_SOURCE_CODES`, `WINDING_RULES`, `HANDLE_MIRRORING`,
    `PROP_KINDS` and `figmaPathError(data)` (null for a Figma path string, else what is wrong).
- **`tools/ir/props.mjs`** (import-free, ES2015; P0 writes it from the Figma API and today's payload, **A owns it
  afterwards**): `KNOWN_PROPS` (per IR type, prop → kind: `num`, `int`, `bool`, `str`, `enum:A|B|…`, `value`,
  `style`, and `own` for an IR-own prop whose rule the schema writes out, §14),
  `RANGE_FIELDS`, `DEFAULTS` (prop → value; a prop may be left out only when it equals its default) and
  `NEVER_OMIT` (`fills`, `strokes`, `strokeAlign`, `strokeWeight`, `clipsContent`, `blendMode`, `textAutoResize`,
  `layoutMode`, `primaryAxisSizingMode`, `counterAxisSizingMode`, written even at their default because Figma's
  defaults differ by type; and `characters`, `fontName`, `fontSize`, `booleanOperation`, `pointCount`, `innerRadius`,
  which have no IR default; the validator refuses a record whose type lists one and lacks it, §14 row 23). The builder writes DEFAULTS explicitly wherever KNOWN_PROPS says a prop
  applies (`ctx.prop` falls back to them).
- `validateIR(ir, {props, maxErrors})`: in v2, `props` is required and it throws without (the tables come in as
  data, so `schema.mjs` stays import-free). `tools/ir/validate.mjs` imports both and exports `validate(ir)` and
  `validateTask(task, {maxChars})`; every Node caller uses it.
- New checks:
  - every node record has `relativeTransform` (6 finite numbers) and finite `width` and `height` ≥ 0;
  - `strokeWeights` and `cornerRadii` are 4 finite numbers ≥ 0; `oracleSides` is 4 booleans;
  - no SUPERSEDED_PROPS, and no `cornerRadius` next to `cornerRadii`;
  - an unknown prop for the type, or a value of the wrong kind, is an error;
  - `vectorNetwork`, `fillGeometry`, `strokeGeometry` and `oracleFillGeometry` only on VECTOR_TYPES (and in
    `derived`); a VECTOR record has exactly one build source (`vectorNetwork` or `fillGeometry`), and a
    geometry-built one carries VECTOR_FROM_GEOMETRY, BOOLEAN_FLATTENED or SOURCE_FEATURE_UNSUPPORTED
    (`GEOMETRY_SOURCE_CODES`); LINE, STAR, POLYGON and BOOLEAN_OPERATION are built natively (a boolean from its
    operands) and carry no build-source geometry; `strokeGeometry` only next to `fillGeometry`;
    `oracleFillGeometry` next to a `vectorNetwork`, or on a natively built type (its stored result, so that §8.3's
    "no oracle means 0 paths" does not fail every native boolean, §14);
  - a VECTOR_ORACLE_DIFFERS note names a network-built VECTOR and its detail starts with its class
    (`ORACLE_CLASSES`: `region-no-fill`, `network-bounds`, `winding`), optionally followed by `: ` and text;
  - a geometry value is `[{windingRule: "NONZERO"|"EVENODD", data: <Figma path string>}]`;
  - `vectorNetwork` is `{vertices[], segments[], regions[]}` with index bounds and closed loops;
  - a text range bound never splits a surrogate pair;
  - IR notes carry read-stage codes only.
- `pages[]` gains an optional `background` (a values index of a fills list; `code.js:47` needs one).
- **Reason codes** (each with a REASON_CODES entry, an IR.md §13 row, `plan: null` and a REWRITE.md sentence in
  `from`, `test-ir.mjs:289-301`):

  | code | stage | meaning |
  |---|---|---|

  | IMAGE_HASH_MISMATCH | read | an archive entry whose SHA-1 is not its name; treated as missing (0 measured) |
  | VECTOR_ORACLE_DIFFERS | read | the stored network and the stored fill geometry disagree in a pre-registered class (§8.3) |
  | SIDE_RULE_UNPROVEN | read | the side rule and the stroke-area path disagree; the IR follows the path (2 / 0 / 0) |
  | BOOLEAN_FLATTENED | read | a boolean carried as one VECTOR from its stored fill geometry; its operands are not carried |

### 5.2 Task format (`tools/ir/task.mjs`, import-free, bundled)

```
TASK_FORMAT = "pix2fig.task"; TASK_VERSION = 1; TASK_OPS = ["fonts","build","verify","clean"]; TASK_IR_VERSION = 2
MAX_TASK_CHARS = 4194304                                   // --max-task-mb lowers or raises it, never above 16 MB (P3)
MAX_TASK_CHARS_CEILING = 16777216; maxTaskChars(mb) -> chars (mb 1..16); taskChars(task) = JSON text length
SERVICE_PAGE_GUID = "m1-service"; IMAGE_SOURCES = ["archive","mcp","render","none"]
TASK_SETTINGS = { layoutOrder, textRead }; TASK_SETTING_DEFAULTS = { textFit:"widen", layoutOrder:"creation",
  textRead:"measure", fallbackFont:{family:"Inter", style:"Regular"} }
BUILD_PHASES = [fonts, images, pages, create, vectors, booleans, layout, settle, measure, repair1, place1, repair2,
  place2, flowGroup, flow1, flow2, repair3, place3, textLine, constraints, stamp]     // §6 B's ms keys, in order
WRITE_ONLY_PHASES = [fonts, images, pages, create, vectors, booleans]                 // no layout read
BUILT_TYPE = { FRAME:"FRAME", GROUP:"FRAME", SECTION:"SECTION", COMPONENT:"COMPONENT", INSTANCE:"FRAME",
  RECTANGLE:"RECTANGLE", ELLIPSE:"ELLIPSE", POLYGON:"POLYGON", STAR:"STAR", LINE:"LINE", VECTOR:"VECTOR",
  BOOLEAN_OPERATION:"BOOLEAN_OPERATION", TEXT:"TEXT" }
task = {
  format, version, op, runId /*16 hex*/, taskNo, of, snapshot /*snapshotId(header)*/, irVersion: 2,
  settings: { textFit, layoutOrder, textRead, fallbackFont: { family, style } },
  page: { index, guid, name, service: bool, background: valueIndex|null } | null,   // null for fonts (and clean);
                                                                   // the service page: guid "m1-service", index null
  roots: [{ i, attachTo: "page" | { i }, place: [x, y] | null }],  // attachTo {i}: a split root's built parent;
                                                                   // "page": top level, and every S2 master
  nodes: [{ i, parent, guid, type, name, props, instance? }],     // IR indices, parent-first; oracle* props stripped
  notes: [{ code, i, detail: string|null }],                      // the IR notes of these records (read stage)
  values: { "<irValueIndex>": value },                            // only the values this task references
  fonts: [{ family, style }],
  images: [{ hash, source: "archive"|"mcp"|"render"|"none", format, reason: string|null }],
  expect: { count, nonInstance, placeholders } | null             // build and verify; null for fonts and clean
}
validateTask(task, { schema, props, maxChars, maxErrors }) -> { ok, errors }   // closed records, enums, size cap;
                       // schema is tools/ir/schema.mjs as data (task.mjs imports nothing); it throws without.
                       // props (tools/ir/props.mjs) closes each record's props to KNOWN_PROPS, of their kinds,
                       // NEVER_OMIT present, as the IR validator does (§14 row 25).
                       // Node: tools/ir/validate.mjs validateTask(task, { maxChars }), both tables passed.
                       // Plugin: PXF_SCHEMA and PXF_PROPS, capped at the ceiling (the runner already cut the
                       // task to --max-task-mb)
```

Per op: a fonts task carries settings and fonts only; a clean task carries its root records only, with their page or
page null (then it does not say where its roots are: `attachTo: "page"` is taken for any of them, S2 masters
included, and the builder looks on every page, §14 row 24); build and verify carry a page, roots, nodes and expect
(`count` = records, `placeholders` = INSTANCE records). A record whose parent is not in the task is a root and only
those are; `attachTo: "page"` needs a top-level record or the service page, `attachTo: {i}` names the record's IR
parent (an index, never -1), `place` only on the service page.

The builder takes a vector's build source from the one geometry prop the record carries and cross-checks it with
`task.notes`: a geometry-built vector without VECTOR_FROM_GEOMETRY, BOOLEAN_FLATTENED or SOURCE_FEATURE_UNSUPPORTED
is a task error. A root's `place` (S2 grid) never enters a comparison: the judge takes every root's own transform as
the origin (`builder4.js:793`, :803).

## 8. Acceptance (`m1-accept.mjs`)

### 8.1 The verdict is a table of gates

`m1Verdict` prints every gate with its number. Any FAIL gate makes the verdict **FAIL** with the gate names. With no
FAIL, the best outcome without a render audit is **BUILT, NOT VISUALLY AUDITED**, followed by the placeholder,
IMAGE_PLACEHOLDER, FILTER_UNRENDERED, FONT_SUBSTITUTED, BOOLEAN_FLATTENED, MASK_UNSUPPORTED and excused-vector counts.
PASS needs an audit report (`--audit`) covering every built root; M1 adds no audit tool, so producing one is the M0
render tooling run by hand (§10). The verdict never prints PASS otherwise.

| gate | measured from | FAIL when |
|---|---|---|
| G1 tasks | `states.json` | a task is failed or skipped (BUILD_FAILED, PLUGIN_STALLED, refused) |
| G2 roots | verify `roots[].found` | a root is not found (ROOT_NOT_FOUND) |
| G3 count | verify `count` against `expect.count` (`builder4.js:800`'s MISMATCH) | any task differs |
| G4 balance | §8.2 | either equation does not add up |
| G5 build failures | build report `failures[]` | any entry |
| G6 position | J `geometry.visibleOver1` | > 0 |
| G7 size | J `geometry.sizeVisibleOver1` | > 0 |
| G8 side strokes | J `sides.mismatchIR + sides.mismatchOracle` | > 0 |
| G9 vectors | J `vectors.differs` (VECTOR_GEOMETRY_DIFFERS) | > 0 |

| G11 placeholders | aligned placeholders against IR INSTANCE records in scope | they differ |

- **Excusing codes are set before VERIFY:** read-stage VECTOR_FROM_GEOMETRY, BOOLEAN_FLATTENED, GEOMETRY_INVALID,

## 11. Risks

- **P0 is serial** and on the critical path (about 1 600 lines with the double core). A surface gap makes B's or C's
  Proxy tests throw; `makeDouble({allow})` covers it, listed in the PR and folded in by F.
- **Vector origin (I).** After `setVectorNetworkAsync` Figma may move the node origin to the network's bounds. The
  judge compares in absolute coordinates, so an origin shift that leaves the drawing in place is not a defect, but a
  drawn shift is; P19B settles the placement rule before step 2.
- **Booleans (A).** Native operations are unprobed in our plugin: a single-operand union (M 9), composed operand
  matrices, Figma's own result against Pixso's (§1.1 shows Pixso stores the operation's result for class A). A
  wrong composition shows up as G6 or G9 failures, not silently. Class B flattening loses operand editability; the
  setting exists for designers who prefer `native`.
- **Text lines are measured, not read.** Figma has no line-count API; countLines is exact only for single-height
  texts. Approximate counts (6 / 15 range entries change line height) are reported apart. The double's 1.0105 ratio
  is a model.
- **KNOWN_PROPS and DEFAULTS may be wrong for some types** (spread on non-frame effects, cornerSmoothing on vectors),
  so the stricter validator could refuse a sound IR. A owns `props.mjs` and runs D, K and M through it before merging.
- **Q5** (API ids = `.pix` guids) is assumed for the render link; the per-run sample tests it and a failure costs
  IMAGE_PLACEHOLDERs (D 3, K up to 21), counted.
- **dynamic-page** changes the behaviour of BUILD, VERIFY, CLEAN and RENDER. If the live smoke test of the M0 sample
  fails, E reverts the manifest line and records why.
- **SHA-1 equality** of the Figma image hash assumes `createImage` keeps hash = SHA-1(bytes) (FINDINGS: 4 of 4). If P4
  or P8 shows re-encoding, the mismatch becomes a counted remap instead of an error.
- **Scope.** By default M1 leaves internal masters with an instance, internal loose nodes and internal state-group
  frames unbuilt (D 2 554, K 16 418 non-instance records), visible in the balance; the 230 / 1 874 masters in state
  groups lose their set until M2b.
- **The 370** cannot be named from the `.pix` alone; without `--legacy-out` the acceptance reports the `.pix`
  population.
- **Time comparisons are not like for like**: the new builder writes more (ranges, explicit defaults, native
  networks), so time per 1 000 nodes may exceed 3.8 / 4.0 s for reasons other than regression. P5 and P6 choices are
  recorded next to the numbers.
- **Liveness** could fail a long single await (a large `setVectorNetworkAsync`, many fonts). The builder calls
  `ctx.progress` before and after every awaited batch, and the ceiling scales with node count.
- **Hygiene.** Synthetic JPEG and WebP bytes and runtime hashes in probes and fixtures must never appear as 40- or
  64-hex literals; hashes are computed at run time.
- **Merge conflicts** come only from a part editing outside §9; test-plugin, selftest and the docs are the likely
  places, and only their owners touch them.
